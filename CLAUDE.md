# nvim-config — Agent & Human Shipyard

## Project conventions
- Neovim config on LazyVim, written in Lua. Plugin specs live in `lua/plugins/`, one concern per file; core options, keymaps and autocmds live in `lua/config/`. Why: LazyVim auto-loads those two locations, so files elsewhere never run.
- Format Lua with stylua using the repo's `stylua.toml` (2 spaces, 120 columns). Why: the file is the single formatting authority.
- Override LazyVim defaults from `lua/plugins/`; leave upstream LazyVim code alone. Why: upstream is not in this repo, so edits there vanish on update.
- Workarounds go in `<plugin>-fix.lua` files whose header comment names the Neovim version and the error text. Why: a later session can then tell when the workaround is safe to delete (see "fix spec" in GLOSSARY.md).
- `lazy-lock.json` and `lazyvim.json` are generated by plugin updates and the LazyVim extras UI. Commit them in their own commit, separate from hand-written config. Why: it keeps config diffs reviewable and lockfile churn revertable.

## Architecture principles
- Load order is lazy.nvim's job: set `lazy = false` only with a stated reason in the spec. Why: `defaults.lazy = false` already loads custom plugins at startup, so extra eager flags add nothing.
- Prefer a LazyVim extra (`lazyvim.plugins.extras.*`, enabled via `lazyvim.json`) over a hand-rolled spec when one exists. Why: extras track upstream changes for free.

## Agent guide
- Delivery follows the canonical workflow plan → execute → review → verify; `/oh-my-claudecode:launch` is an optional governed delivery pipeline (opt-in, invoke explicitly)
- On term conflicts GLOSSARY.md wins; new terms are recorded the moment they settle
- When a deferred surface first appears (standards, decision records, business knowledge, project skills, the design system), it gets an index section here at the moment it is created — never before
- Verify a config change by running `nvim --headless +qa` and checking that it prints no errors, then opening `nvim` once and running `:checkhealth lazy`; done means no error output from either. Do not run `Lazy sync` or `Lazy update` to verify: they rewrite `lazy-lock.json`.
- Issues and PRs live on GitHub at `Towerism/nvim-config`; branches follow `feature|fix|hotfix|docs|chore/{issue}-{slug}`.
